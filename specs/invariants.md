# Invariants

What must stay true of glave whatever changes, each with the test that proves it. The other specs say how each piece works; this one gathers the promises that span them, so a reviewer can check a change against one list.

## Status

Written from the architecture pass of 2026-10-18 (#395). Each invariant says whether it holds today: **holds**, **partly** (with the gap) or **not yet**, and names the issue that closes a gap. A change that touches an invariant says so in its pull request and keeps its test; one that closes a gap moves its entry to **holds** and names the new test.

## Where state lives

Every invariant below follows this rule (decided 2026-10-18).

- **State at rest lives in the store,** the event log on SQLite or Postgres, and nowhere else: no Redis, no second system. A file under `GLAVE_HOME` holds a decision only while it is listed below as a gap.
- **Work in flight runs under a lease recorded in the store:** a row with a holder and an expiry, on the database's clock, the same on SQLite and Postgres.
- **LISTEN/NOTIFY only wakes.** Another process may be woken by it, but correctness never depends on it: the log is the truth.
- **OS file locks only for machine resources,** such as `server.lock` for the socket and port.
- **Files only for what cannot live in the store:** `root.key`, which unlocks it, and this machine's own state, never shared through an organization's database (`computer`, `run/processes/`, `serve.token`, `serve.url`, `open.html`, `worktrees-checked`, the locks), and each worktree's record beside it (`<worktree>.json`), which describes the disk of the computer that holds the worktree: a remote computer cannot reach the store, and who owns a worktree is already in the log (`workspace.bound`). The write-once ones, `root.key` and `computer`, are created whole or not at all (`glave_ports::file`); the rest are written anew at each start or check, so a torn one is rewritten, and a process record that cannot be read is skipped. A worktree record is replaced whole (`glave_ports::file::replace`); a torn one is read as none and written whole at the next open or hold. Proved by `crates/ports/src/file.rs` `a_create_stopped_at_any_step_leaves_no_file_or_a_whole_one`; `crates/keys/src/root.rs` `a_key_file_whose_creation_stopped_at_any_step_opens_cleanly`; `crates/cli/src/identity.rs` `a_computer_id_whose_creation_stopped_at_any_step_is_read_or_made_whole`; `crates/cli/tests/serve.rs` `torn_token_and_address_files_are_written_anew_at_start_and_work`; `crates/cli/src/worktrees/cleanup/tests.rs` `a_torn_check_stamp_is_checked_again_and_written_whole`; `crates/process/src/processes/tests.rs` `an_entry_that_cannot_be_read_is_skipped_and_the_others_are_still_stopped`; `crates/computer/src/worktrees/tests.rs` `a_torn_record_is_read_as_none_and_written_whole_again`.
- **No deltas in the database.** Token-by-token deltas go to watchers live and are never stored; the events they add up to are.

## The invariants

Tests are named by file and function. A conformance suite is a function in `crates/ports/src/conformance.rs` (or `conformance/`) that every adapter's own test runs, so it binds the in-memory store, SQLite and Postgres alike.

1. **The log is the truth, and everything in memory is a cache of it**: views, thread slots, ledgers, memory books, meter streams.
   - *Partly.* Within one process it holds. State with no log behind it remains: idempotency keys and in-process gateway budgets (#410), queued messages (#335), and the context window a refusal stated for each model. Worktree records stay on the computer that holds the worktree, as the computer's own state (above). The local person's and their agent's ids are kept in the store, and so are project trust (`crates/cli/tests/postgres.rs` `two_homes_on_one_database_read_one_trust_record`) and browser sessions (`crates/store-postgres/tests/postgres.rs` `a_browser_signed_in_on_one_server_is_signed_in_on_another_on_the_database`) (`crates/store-postgres/tests/postgres.rs` `servers_on_one_database_racing_to_make_the_identity_all_get_the_first`).
   - *Proved by:* `conformance::thread_views` ("a rebuilt view must be stored"); `crates/session/tests/server.rs` `a_fresh_server_continues_a_thread_from_the_log_alone`; `crates/harness/tests/turn.rs` `a_resumed_thread_continues_where_it_left_off`; `crates/memory/tests/loading.rs` `returning_after_changes_gets_a_note_and_resuming_rebuilds_the_same_requests`; `crates/gateway-service/tests/surfaces.rs` `each_caller_has_their_own_budget_and_a_restart_does_not_reset_it`; `crates/store-sqlite/src/tests.rs` `views_rebuilt_from_the_log_equal_the_kept_ones`.
2. **One writer per thread, enforced by the store**: a thread's `seq` is gap-free and unique, checked in the append's transaction.
   - *Holds* at the store, for writers racing on every store: the shared suite starts them together, so a store whose check and write are not one step fails it.
   - *Proved by:* `conformance::event_log` (conflict, gap, all or nothing, and racing writers: exactly one takes the place, every other is told of the conflict), run by the in-memory log, SQLite and Postgres.
3. **One harness at a time per thread, under a lease**; another server is refused (`-32011`).
   - *Holds* for work on a thread: a turn, a compaction or a change to the thread runs under the thread's lease (`glave_ports::Leases`), renewed while it runs; another server asking to work on it is refused. Tasks are recovered, and schedules fired, under leases too (13).
   - *Proved by:* `crates/session/tests/leases.rs` `a_second_server_reads_a_thread_another_runs_without_writing_and_is_refused_its_turn`, `a_turn_left_open_is_closed_as_the_server_starts_once_no_live_lease_holds_it`; for the leases themselves, `conformance::leases` (one holder at a time, renewing and letting go only by the holder, a lapsed lease anyone's, racing holders leaving it with one), run by `crates/ports/src/in_memory/leases.rs` `in_memory_leases_pass_the_leases_suite`, `crates/store-sqlite/src/tests.rs` `the_leases_pass_the_leases_conformance_suite` and `crates/store-postgres/tests/postgres.rs` `the_leases_pass_the_leases_conformance_suite`; across processes, `crates/store-sqlite/src/tests.rs` `processes_on_one_file_share_its_leases` and `crates/store-postgres/tests/postgres.rs` `servers_on_one_database_racing_for_a_lease_leave_it_with_one`.
4. **No side effect runs twice without the person**: an interrupted call is closed, never redone, and a retry with the same key never starts a second turn.
   - *Partly.* It holds in one process, where each person's keys are kept in a pool of their own, so no one's flood of keys pushes out another's, and across servers for turns left open, which only the holder of a thread's lease closes. Keys kept in memory still let a retry reaching another server start a second turn (#410).
   - *Proved by:* `crates/harness/tests/turn.rs` `resuming_after_a_crash_records_nothing_and_the_next_turn_closes_what_was_left_open`, `repairing_closes_a_turn_left_open_once`; `crates/session/tests/leases.rs` `work_on_a_thread_left_open_closes_it_first`; `crates/session/tests/durable/crashes.rs` (a turn, alone and with two subagents side by side, stopped at every event boundary: no call runs twice); `crates/session/tests/server.rs` `a_retry_with_the_same_key_follows_the_running_turn_instead_of_starting_one` (one process); `crates/session/src/keyed.rs` `one_persons_flood_never_evicts_anothers_key`.
5. **Reading never writes.**
   - *Holds* for threads: loading one (`thread/get`, `thread/list`, `thread/events`, a watch) records nothing; what a turn left open is closed only by work under the thread's lease, or as the person's server starts. `command/list` still records what it finds ended (`session.md`, "Commands in the background").
   - *Proved by:* `crates/session/tests/leases.rs` `a_second_server_reads_a_thread_another_runs_without_writing_and_is_refused_its_turn` (two servers on one store, a turn running on the first), `a_turn_left_open_is_closed_as_the_server_starts_once_no_live_lease_holds_it`; `crates/harness/tests/turn.rs` `resuming_after_a_crash_records_nothing_and_the_next_turn_closes_what_was_left_open`.
6. **Scope is enforced by the store on every query, and no organization sees another's data, nor any person another's.** Only `locate` takes a bare thread id. Something in a project the caller does not work in is answered exactly as something that does not exist, so not even its existence leaks.
   - *Holds* for the log, blobs, views and search, and for every method of the session API: two organizations on one store, two people each, every method called by every person with every other person's ids, on SQLite and Postgres. Projects are asked by organization, and membership is checked by the session. Across organizations it is proved for two servers sharing one store; one server serving many organizations, each caller's from their sign-in, comes with #423, and Postgres row-level security keyed by organization with it, as designed in `storage.md` ("Row-level security").
   - *Proved by:* `conformance::event_log` ("another scope must not see this thread"); `conformance::blob_store`; `conformance::thread_views` ("views must not cross scopes"); `conformance::search` ("a search must stay inside its scope"); `conformance::memory_scopes` (memory enforces scope itself: a project's memory stays in its project, a person's own with them and in their organization, what someone may not reach answers as missing, and a result kept by reference reads again only what the thread reading it may), run by `crates/memory/tests/conformance.rs` `glaves_memory_passes_the_scope_suite`; `crates/session/tests/isolation.rs` `on_sqlite_no_one_reaches_anothers_data`, `on_postgres_no_one_reaches_anothers_data`, and `every_method_and_every_id_it_takes_is_in_the_table`, which fails for a method or an id param the suite does not call; `crates/session/tests/many_projects.rs` `one_person_can_neither_read_nor_answer_anothers_threads`; `crates/session/tests/list_watching.rs` `nobody_hears_of_threads_in_a_project_they_do_not_work_in` (a watch of every project the caller works in, which names no id for the suite to fill), `someone_taken_off_a_project_stops_hearing_of_it_within_a_minute`; `crates/session/tests/listing.rs` `a_cursor_says_nothing_of_anyone_elses_activity_and_pages_list_each_thread_once` (a list's cursor carries only its own last row, never activity elsewhere in the store).
7. **In-process and remote are one code path**: the same scenarios on every transport, the same suite on every computer.
   - *Holds* for the session API on all four transports, and for local and remote computers and workers (`WorkerComputers`, on the in-process backend that serves a worker as a container would).
   - *Proved by:* `crates/session/tests/conformance.rs` (in-process, stdio, Unix socket, HTTP and SSE); `crates/session/tests/watching.rs` and `list_watching.rs` (watches of a thread and of a list, on the same four); `conformance::computers`, run by `crates/computer/src/local/tests.rs` `this_machine_passes_the_computers_suite`, `crates/computer/tests/remote.rs` `a_computer_across_a_pipe_passes_the_suite`, `a_computer_over_tcp_passes_the_suite_once_signed_in`, `a_computer_over_tls_passes_the_suite_with_its_certificate_pinned`, `crates/computer/src/worker/tests.rs` `workers_pass_the_computers_suite`, and `crates/cli/tests/computer.rs` `the_binary_serves_a_computer_that_passes_the_suite`.
8. **Secrets never reach logs, clients, `Debug`, the model or a command's environment.**
   - *Holds,* as far as tested.
   - *Proved by:* `conformance::model_provider` ("the key the server repeated shows in the error"), run by `crates/provider-openai/tests/client.rs` and `crates/provider-anthropic/tests/client.rs` `the_provider_passes_the_model_provider_suite`; `crates/cli/tests/telemetry.rs` `the_log_has_spans_and_metrics_and_never_content`, `a_collector_gets_spans_and_metrics_and_never_content`; `crates/session/tests/http.rs` `the_signed_in_caller_is_recorded_and_the_token_never_is`; `crates/session/tests/credentials.rs` `a_token_never_shows_in_a_request_s_debug`; `crates/session/tests/providers.rs` `a_key_never_shows_in_a_request_s_debug`; `crates/computer/src/local/confinement_tests.rs` `commands_never_see_secret_variables`; `crates/computer/tests/remote.rs` `a_computer_across_a_pipe_keeps_secret_variables_from_commands`, `a_computer_over_tcp_keeps_secret_variables_from_commands`; `cargo xtask secrets`.
9. **Content at rest is sealed,** bound to its row by associated data, so a sealed payload moved to another row does not open.
   - *Holds* in both stores, and any store is held to it by the ports suite: payloads and blobs sealed, a payload moved to another row, thread or project refused, and each blob kept under a keyed name with every thread that stored it; a blob's chunks bound to their object and place.
   - *Proved by:* `conformance::at_rest`, run on each store's own rows by `crates/store-sqlite/src/tests/sealing.rs` `the_file_passes_the_at_rest_suite` and `crates/store-postgres/tests/sealing.rs` `the_tables_pass_the_at_rest_suite`; `glave_keys::conformance::keys`, run by `crates/keys/src/keys/tests.rs` `in_memory_keys_pass_the_conformance_suite` and both stores; `crates/keys/src/keys/blob/tests.rs` `bytes_cut_short_reordered_moved_or_of_other_content_do_not_open`.
10. **Ledgers are glave's own streams**: never listed or read as threads; any process may append to one, and a conflict retries.
    - *Holds.*
    - *Proved by:* `crates/session/tests/schedules.rs` `the_task_ledger_is_never_listed_or_read_as_a_thread`; `conformance::thread_views` ("a stream without thread.started must have no view").
11. **Records from outside never change the conversation**: only glave's own record kinds are taken in while a turn holds the thread, and a message from outside is a conflict; a thread held idle is read again by work that takes its lease.
    - *Holds.*
    - *Proved by:* `crates/session/tests/outside.rs` `glaves_own_records_are_taken_in_and_the_model_is_sent_the_same`, `a_message_from_outside_is_still_a_conflict`.
12. **Waits are durable**: an approval or a question survives a restart and is answered from the log.
    - *Holds* on every store: a turn stops at what it asks and holds nothing; an answer to any server records it and goes on with the turn from the log; a subagent's wait holds its parent, and a subagent never runs twice.
    - *Proved by:* `crates/session/tests/durable.rs` `in_memory_waits_survive_a_restart`, `on_sqlite_waits_survive_a_restart`, `on_postgres_waits_survive_a_restart` (an approval, a question, a denial and a subagent's approval through a stop and a new server, each run's events those of a run never stopped but for ids and times; two subagents side by side, the running one reported interrupted and never started again; Needs you right after the restart); `crates/session/tests/durable/crashes.rs` `a_turn_stopped_at_any_boundary_is_waiting_or_interrupted_and_no_call_runs_twice`, `subagents_stopped_at_any_boundary_never_run_a_call_twice`.
13. **One firer per schedule and one recoverer per task.**
    - *Holds* across servers on one store: schedules fire only from the holder of the organization's scheduler lease, and a task is recorded interrupted only under its thread's lease, which its running turn holds wherever it runs. On one computer `server.lock` still keeps one person's server per glave folder.
    - *Proved by:* `crates/session/tests/schedules.rs` `schedules_fire_from_one_server_at_a_time`; `crates/session/tests/tasks.rs` `recovering_tasks_covers_every_project` (two servers on one store: the second waits for the first's leases to lapse).
14. **Every spawned task and process has an owner** that awaits or stops it.
    - *Holds* for every `tokio::spawn` read in the pass, and for every process, which starts only through glave-process.
    - *Proved by:* `cargo xtask spawns` for processes; nothing checks tasks.
15. **Everything persisted or sent carries a version.**
    - *Partly:* events, the session protocol, the computer protocol, the process ledger and worktree records do (a worktree record with no version is read as none and written whole again, and one of a newer version is refused). The `computer` file is one id, created once, with no version.
    - *Proved by:* `crates/event/tests/fixtures.rs` `every_known_version_has_a_fixture_that_decodes`, `latest_versions_encode_to_exactly_the_saved_bytes`, `every_fixture_is_a_known_version`; `crates/store-sqlite/src/tests.rs` `a_file_of_another_schema_is_refused_and_left_as_it_was`; `crates/computer/src/worktrees/tests.rs` `a_record_of_a_newer_version_is_refused_plainly`.
16. **Time and randomness are injected.**
    - *Partly:* library code in glave-computer and glave-process still reads the real clock (a lint in #366). Randomness that fails is an error, never a weaker id.
    - *Proved by:* nothing enforces injection; tests use `glave_ports::testing::ManualClock`. `crates/harness/tests/turn.rs` `a_random_source_that_fails_makes_no_thread`.
17. **A scope is only used after its membership was checked:** the caller is in the project (as its owner or a member), the project in the caller's organization.
    - *Holds* in the types: `Scope`'s fields are private, and stores and the harness take nothing else. A scope is made two ways only: `Scope::of_member`, which checks that a person works in a project read from the store, called from the session's one check (`Server::authorized`, which `allow` runs before any request on a thread or project is read or recorded), and `Scope::glaves_own`, for glave's own work no one asks for at that moment (the scheduler, ledgers, recovery, the host opening its own folder, views rebuilt) and tests; every call outside tests says why. `EventLog::locate` answers a `Located`, not a scope. What remains is by hand: the session's `scope_of` hands glave's own scope to the work that follows a request's check, so the check in `allow` must stay the first thing every request on a thread meets, which the isolation suite proves for every method. Teams and the caller's own organization join the check with #222 and #423.
    - *Proved by:* `crates/ports/src/scope.rs` `only_the_owner_and_members_get_a_scope_and_it_is_the_projects_in_its_organization`; `crates/session/tests/isolation.rs` (every method, every other person's ids); `conformance::event_log` (`locate` answers where, not a scope).
18. **Nothing outlives what started it** (#558): every process glave or its tooling starts ends when its starter ends, however that ends (an exit, Ctrl-C, SIGTERM, SIGKILL, a crash, a tool's timeout), at once, not at a later start.
    - *Partly.* Holds for what glave starts to run on its own (commands, commands in the background, MCP servers, and all each started that stays in its group, sandboxed or not; keeping the computer awake): its lifeline's helper stops them at once, and the ledger at the next start when the helper went too (`one-server.md`, "No orphaned processes"). Holds too for what `cargo xtask` runs and the eval's commands, tied by the same lifeline, and for glave started by its tests and the end-to-end runs: each is handed its starter's lifeline and ends with it, whether the starter ends on its own or is killed outright. Not yet: workers on Docker or Kubernetes (#568), helpers glave waits for (git, setup scripts; #569).
    - *Proved by:* `crates/cli/tests/starter.rs` `a_glave_and_the_person_s_server_it_starts_end_with_what_started_them`; `npm run e2e:killed` (`web/e2e/killed.mjs`: a runner that ends and one killed outright leave nothing, in CI's first Chromium shard); `crates/cli/tests/orphans.rs` `a_glave_killed_outright_has_what_it_started_stopped_at_once`, `a_glave_killed_outright_has_its_sandboxed_commands_stopped_at_once`, `a_glave_killed_outright_has_its_landlocked_commands_stopped_at_once` (CI's Landlock job), `when_glave_and_its_helper_are_killed_the_next_start_stops_what_they_left`; `xtask/tests/killed.rs` `what_xtask_runs_ends_when_xtask_is_killed_outright`; `crates/eval/tests/lifeline.rs` `the_eval_s_program_is_its_own_lifeline_helper`; `crates/process/src/lifeline/tests.rs` `the_helper_stops_what_glave_still_held_once_its_end_closes`, `once_glave_reaps_a_leader_its_group_alone_is_held_until_let_go`, `the_helper_stops_the_group_of_a_leader_glave_reaped`, `glave_tells_its_helper_what_it_holds_and_a_new_helper_all_it_still_holds`, `a_program_that_cannot_be_the_helper_is_refused_before_anything_starts`.
19. **Erasure erases** (`storage.md`, "Erasure"; `memory.md`, "Seeing, editing and forgetting"): what is erased can no longer be opened, in the store or a backup; and a forgotten memory's text is nowhere memory put it, and found again through nothing memory showed. Its own events, sealed under its own key, are the only copy memory writes: a memory tool's result that showed it is kept by reference and read again as it is now (#578). Chats are history (#630): a forget erases none of what the person and the model said, and `recall` finds it until its chat is deleted, after which no search finds it and no earlier result reads it again.
    - *Partly.* Holds for a project's content and a memory. A backup loses a forgotten memory's key at the next rotation of the project key, which housekeeping batches (within a day). What glave forgets itself (tidy-up, retention) is erased 30 days on, restorable until then. What the person and the model said stays, by decision (`memory.md`, decision 7), until the person deletes its chat: their messages, the model's calls (a save's or an edit's text is its argument) and the summary of an approval it asked for. A deleted chat is found by nothing, but its content stays sealed in the log until data keys are per thread (`storage.md`, "Erasure"). A thread held open keeps what it was shown, in memory, until it is read again.
    - *Proved by:* `glave_keys::conformance::keys` (an erased project's content and a destroyed data key's no longer open; new keys never reuse a number), run by `crates/keys/src/keys/tests.rs` `in_memory_keys_pass_the_conformance_suite` and both stores; `crates/memory/tests/store.rs` `forgetting_destroys_the_key_so_no_version_can_be_opened`; `crates/memory/tests/recall.rs` `a_forgotten_memory_s_chat_is_history_until_it_is_deleted_too`; `crates/memory/tests/tidy.rs` `forgetting_what_a_merge_made_erases_what_went_in`; `crates/memory/tests/kept.rs` `a_forgotten_memory_is_never_found_again_through_an_earlier_recall` (a save's and a recall's results keep no copy in the log or the index, and once its chat is deleted too, a thread read again shows the model none), `a_kept_recall_reads_again_only_what_its_reader_may_read` (past conversations named by place, read back from the log, show only what the reader may); `crates/memory/tests/loading.rs` `a_near_duplicate_s_and_an_edit_s_results_keep_no_text_and_read_the_same_resumed`, `returning_after_changes_gets_a_note_and_resuming_rebuilds_the_same_requests` (a forgotten memory drops out of a resumed thread's start); `conformance::memory_scopes` (a kept result holds no memory's text and reads again only what the thread reading it may), run by `crates/memory/tests/conformance.rs` `glaves_memory_passes_the_scope_suite`; `crates/session/tests/memory.rs` `a_saves_result_shows_the_person_its_text_until_they_forget_it` (a client is shown a save's text, read again for the caller, and none once it is forgotten), `forgetting_leaves_the_chat_a_memory_was_saved_in_named_while_it_is_there`.
