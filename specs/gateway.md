# Gateway

The single door out for model calls and remote tools: which model serves each purpose, with whose keys, within what budget, and what it cost; and the tools that reach the outside world (search, image generation, speech, an organization's own systems), each with credentials only the gateway holds. Runs inside glave, for a person and for an organization's server alike: glave has no gateway service of its own ("No service of its own").

The seam: the harness owns the tools that act on the computer and the rules for using any tool; the gateway owns everything that leaves for the outside world.

## One default seam

Decided by the owner, 2026-10-19 (#392): **OpenAI's API is the one default seam for models.** glave speaks Chat Completions to OpenRouter, OpenAI, Azure, Bedrock's and Vertex's compatible endpoints, and any server that copies them (Ollama, LM Studio, vLLM, an organization's own).

- **"Add a model" offers OpenRouter and any OpenAI-compatible server up front** (and OpenAI's own). A model's capabilities and price come from the service's model list ("Catalogs"), so a new provider needs no code when it speaks the seam.
- **A native format is an exception that must justify itself:** only where the compatible path loses something material, such as prompt caching, reasoning sent back, or an enterprise route served no other way. Anthropic's Messages API is one today, for Claude on Bedrock and Vertex (served only that way) and a direct key; it stays an internal route, not offered to add, and is expected to go once the routes glave uses no longer need it.
- **No new native format** without that justification written here first.

## No service of its own

Decided by the owner, 2026-11-08 (#1318): **glave has no gateway service of its own.** A company that runs a gateway (LiteLLM and the like) connects glave to it as an OpenAI-compatible server; pointing other agents at a person's or an organization's glave is #317, after v0.1, on the one server.

## Routes

A **route** names a purpose and maps it to an ordered list of **targets** (provider, model, region, credential reference), each with what it can do (tools, reasoning, images, context size).

- Purposes are a stable public vocabulary: `main`, `judge`, `summary` (compaction), `subagent`, `title` (a thread's title, `session.md`), and later `voice.listen`, `voice.speak`. A purpose with no route uses `main`.
- Routes are choices (nearest wins) and the models they may name are constraints (`policy.md`).
- **Choices.** Besides its routes, the gateway may offer targets a thread may choose (`session.md`, "Choosing a model and permissions"): in-process, the judge's model when it is another, and each of `[[models]]`. A call whose purpose uses `main`'s route and that asks for a choice by its name or model goes to that target alone; a purpose with a route of its own keeps it, and a call asking for `main`'s first model, or for any model that is not a choice, goes by its route as before.
- `model.responded` records the route and the target that actually served each call, so fallback is auditable.

## Fallback

- **Capability-checked:** a target that cannot honour the request (no tools, a smaller context than the conversation) is skipped, never sent a degraded request.
- **Thread-sticky:** a conversation that holds a provider's opaque reasoning falls back only to targets that accept it. Otherwise the reasoning is stripped explicitly and that is recorded.
- Failures that may pass (rate limits, overload, timeouts) move to the next target after the provider's own retries. Never once output has come: an answer that breaks off partway goes to the caller as it is, since asking again, here or in the harness, would paste a second answer after the first's start.

## Catalogs

What a model can do and costs is the provider's to say, never glave's: its context window, longest answer, whether it reads images, its price and the levels of reasoning effort it offers come from the service's own model list, read the same way from every service (OpenRouter's `GET /api/v1/models` says all of it, Anthropic's `GET /v1/models` its effort levels, vLLM its context, most services little beyond the id). Nothing about a model is written into glave's code.

- **Kept in the store**, never in a cache server of its own: one catalog per service a person connected (its kind, and its URL for another server), each with when it was listed and its models as the list described them, in the catalog ledger (`events.md`). Only the latest `catalog.refreshed` is read.
- **A server's own OpenRouter has a catalog too:** when the endpoint a server's settings choose is OpenRouter itself, as on Glave Cloud, it is read and offered as a person's account is, with the server's key, and its catalog kept beside theirs. No one connected it, so it is never kept as an account or listed as anyone's. On a server that keeps credits it offers every model its catalog lists, unless the settings name the models to offer (`[[models]]`), then those, the main model and the judge's; elsewhere only those, so choosing one model in the settings never offers everyone the rest on the server's key. Until its first listing its main model has no price, so a server that keeps credits refuses its calls for that moment; `model/list` and every turn start that listing.
- **Listed when an account is added**, by the call that checks its key; **daily**, when the server is next asked for its models or starts a turn after a catalog grew a day old, in a task no one waits for; and **on demand** (`provider/refresh`). A service that cannot be reached keeps its catalog and is tried again an hour later; one that answers the same is not written again.
- **A router's endpoints:** OpenRouter serves most models from several providers, each with its own precision, context, price, speed and data policy. Its catalog keeps, beside the models, OpenRouter's providers (`GET /api/v1/providers`: each one's slug, name, the country it is based in and the countries of its datacenters, where OpenRouter says them; datacenters it does not name are unknown, never guessed), and each model's endpoints (`GET /api/v1/models/{id}/endpoints`: its provider, how its weights are stored, its context, longest answer, price and median speed over OpenRouter's last half hour), each marked as keeping nothing where OpenRouter lists it so (`GET /api/v1/endpoints/zdr`); an endpoint that takes no tools is left out, since glave's calls may use them. They are read when the catalog is listed, a few models at a time, all within two minutes. When the providers or the endpoints that keep nothing cannot be read, the catalog keeps what it had and is listed again an hour later, as nothing of a model's would be known; a model whose own endpoints are not read keeps those it had, and when the two minutes ran out first, the catalog is listed again an hour later too. A median speed changes with every listing, so a catalog whose speeds alone changed is not written again. Adding an account lists its models alone, so it stays quick, and the refresh it makes due reads the rest. `model/list` says each model's endpoints with where each provider is based, so a client can filter by them; the precision is glave's reading of OpenRouter's name for how the weights are stored (four, six or eight bits, full, or unstated).
- **An account's models are its service's catalog's**, those glave can talk with, newest first, at most a thousand: a model the service adds shows up from the next refresh, with no new glave and no reconnecting.

## One entry per model

The same model can be reached at several services (Claude Haiku from Anthropic or through OpenRouter, GPT from OpenAI or OpenRouter, an open model from OpenRouter or a person's own server). A person chooses the model; glave chooses the route (#289).

- **One name across services:** the id without its maker's prefix, in lower case, dots as hyphens, without a date at its end, so `claude-haiku-5-5-20261007` and `anthropic/claude-haiku-5.5` are one model. Ids that differ more show once per service.
- **Route order:** the settings' model (an organization's cloud contract) first, then the maker's own API (OpenAI, Anthropic), then an aggregator (OpenRouter), then any other server. A later service serves only when the one before fails in a way that may pass, by the fallback above; the entry's `id` is the first service's.
- **What `model/list` says of it** comes from the catalogs: its own name and maker (OpenRouter's `Anthropic: Claude Haiku 5.5`; a name the settings give over it, which may name its maker the same way), and where neither names it, the server writes them from its id as its maker would (`openai/gpt-6-luna` is OpenAI's `GPT-6 Luna`), so every entry has a name and no client names a model from its id; the services in that order, its context, longest answer, images and reasoning levels from its first service's catalog, else from another's for the same model (the levels its first target is sent, where that target has some of its own, as a cloud contract's Claude does with no catalog), and its price and the level it is sent unasked from the first service's alone, since that is where a call goes. The gateway checks requests against the same context and images, holds credits at that price, and records it as the price list (`<service> catalog <date>`) when the provider reports no cost of its own.

## Reasoning effort

Decided by the owner, 2026-10-24 (#703): when a model's default level is known, glave sends it explicitly, rather than leave it to whichever provider serves the call, and shows it; when no catalog says it, glave sends none, and a client says the model reasons by its maker's default.

- **Known only from a catalog.** OpenRouter's listing says the level reasoning starts at (`default_effort`) and whether the model reasons unasked (`default_enabled`, `mandatory`), so the level it uses unasked is that one when it reasons unasked, `none` when it does not (or its `default_effort` is `none`), and unknown when the listing does not say. Nothing about a model is written into glave.
- **Each target's own catalog, never another service's.** OpenRouter's level names are its own, each mapped to the nearest one the provider behind it takes; OpenAI's API takes its own levels for each model, refuses others and defaults differently. A target whose catalog names no levels, such as OpenAI's own API, is sent none, even when another service's catalog for the same model names a default; sending one would guess. So is a target with no catalog at all, a cloud contract's (`[provider]`), but for Claude (below).
- **Claude** (#708; Anthropic's docs read 2026-10-25: effort, thinking, the model list). A level goes as `output_config.effort` with `thinking: {"type": "adaptive"}`, so it sets how much the model thinks. Later models think adaptively unasked, so on them asking for their default level is the same as asking for none; Claude Opus 4.6 to 4.8 and Sonnet 4.6 think only when asked, so there a level turns thinking on and none leaves it off. The levels offered are those Anthropic's model list marks supported (`capabilities.effort`) on a model that takes adaptive thinking. One the list says takes no level, or only extended thinking (4.5 and earlier, which refuse `adaptive`), is offered none, whatever another service offers for it. Bedrock and Vertex AI list no models this way, and a key set in the settings has no catalog, so Claude there is offered the five levels Anthropic documents (`max`, `xhigh`, `high`, `medium`, `low`); a model that does not take the one picked refuses it, and the person sees the API's own message. Anthropic's list names no default, so a thread that chooses none is sent none.
- **The gateway applies it**, from the target, so every caller through it gets the same: on every call of every purpose, a level asked for that the target offers, else its model's default, else none. The person's pick wins wherever it can be sent. The default is the level the service's catalog names as the model's own, so a call that asks for none, the judge's and titles' among them, is sent that level.
- **What is sent is said:** `model/list`'s `reasoning.default` is the level a thread that chooses none is sent at the model's first service, absent when glave sends none; `model.responded` records the level each call was sent with (`effort`).

## Keys

- The gateway resolves credentials; nothing that calls it ever holds them.
- **Sources:** the OS keychain for a person; environment, a KMS, a secrets manager or workload identity for an organization; short-lived tokens refreshed outside the request path.
- **Cloud contracts are targets like any other:** Amazon Bedrock, Azure OpenAI, Google Vertex, and the company's own vLLM. That is how "data on our servers, models through our cloud contract" works (below).
- **How a provider is reached** (`glave_ports::auth::Auth`): nothing (a local server), a fixed key in the header the provider wants (`Authorization: Bearer`, Azure's `api-key`, Anthropic's `x-api-key`), or credentials that change: each request asks them for its headers, so one interface carries a bearer token refreshed before it expires (Entra, later Google) and a signature over each request (AWS SigV4). Credentials are kept until five minutes before they expire, and fetched outside any lock. A failure to get them is refused (`ProviderError::Credentials`) or, when the source could not be reached, passing.
- Keys and tokens never show: not in `Debug`, logs, errors or answers; header values are marked sensitive.

## Cloud contracts

`[provider]` in the person's or the server's own `config.toml` (never a project's: the organization's credentials go there) names a cloud's models in place of `GLAVE_BASE_URL`'s server; with both set glave refuses, naming both. Each model is reached through the cloud's OpenAI-compatible Chat Completions, so the requests are the ones glave sends any such server, except Claude on Bedrock and Vertex, which those clouds serve only through Anthropic's Messages API. The model is named as that cloud names it, and `[models]` rules see `azure/<deployment>`, `bedrock/<model id>` or `vertex/<model>`.

## Budgets

- **No budget is kept today.** An organization's spending is held by its credits ("Credits", below); the per-person daily budget went with the gateway service (#1318).
- **A person's monthly budget (#662) and the others** (an organization's, a project's, a thread's within the threads above it, a worker's, limits in tokens) **wait for the first organization that needs them.** Each will be held and settled as credits are, and read back from the log after a restart.
- **Exact, and never past the limit of what can be counted.** A hold and a cost are nanos. A cost rounds up to the next nano, so a call that cost anything never counts as free. A sum that would not fit in 64 bits stops at the most there can be.

## Credits

Decided by the owner, 2026-10-29: on Glave Cloud people use Glave Cloud's own models and key, and pay for what they use. No subscription and no base fee: an organization pays ahead for credits in US dollars, bought by card. Model calls are charged at cost, the provider's own reported cost (OpenRouter's `usage.cost`), with no markup. Each organization has a monthly spending limit, about $10 unless its Owner raises it. Compute, disk and other infrastructure are charged later, at a markup. Card payments and topping up on their own come later, through Polar, from a billing service of their own that calls glave's admin API. Built by #1054:

- **Only where the server's own configuration says so** (`[credits]` in its `config.toml`, never a project's): `monthly_limit_usd`, the limit each organization starts with, is the server's own number, as no price or limit is written into glave. Without the table nothing changes: no balance, no refusal, nothing new to see or click (principle 4).
- **The credits ledger** is one stream of the organization's own, beside its people ledger (`events.md`): money added, the limit its Owner set, and each charge with its kind of cost (`model` today, `media` for the media tools once built, so compute and disk join the same balance later) and whose work it was. The balance is everything added less everything charged; the month's spending, everything charged since the month began in UTC. Amounts are exact, in nanos, billionths of a dollar (`events.md`, "Money"); cents are only for showing them.
- **Reserve, then settle, against both.** Before a call is sent, its worst case at its target's price is held against what calls running leave free of the balance and of the month's limit, on every server on the store: the hold is a `credits.held` in the ledger, appended only once everything before it was read, so of servers racing for the last of a balance one holds it and the others read its hold before they hold. It is refused before it is sent, with a sentence a person acts on (`-32020`, `failure: over_budget`): when nothing is left of the balance ("you're out of credits"), even for a call priced at nothing; when the month's limit is spent ("this month's spending limit of $10.00 is reached"); or when its worst case is more than what is free now, saying both, what it needs rounded up to the cent and what is free rounded down. A model whose price no catalog says is refused too, since no one can say what its call could cost, and the next target that has a price serves it instead: on a server that keeps credits, its models are those of its own OpenRouter and of model accounts, whose catalogs price them. `model/list` still offers one with no price: a gap.
- **What a call costs** is its provider's reported cost in dollars, else its usage at its price, counted in this server's book at once in its hold's place, and written to the store after, its `credits.charged` naming the hold it lets go of for every server, each charge with the id it was first written with, so one whose append landed unseen is read back in its count's place, never written twice; one the store does not take stays counted and is written with the next. A call cancelled once sent is charged what it read and what came of its answer's text, at its price, as its provider charges for them; one that broke off after its answer began, the same; one that failed before any came, nothing. What came of a call to a tool is not counted until the answer ends: a gap. A reported cost above the hold takes the balance below nothing, by that much.
- **Who pays:** every call a thread makes, its judge, title and compaction summaries included, is charged to the thread's organization for the person it works for; memory's tidy-up for the person whose memory it tidies. A call no organization asked for is charged to no one.
- **Adding credits** is one admin operation: an amount, the reference of the payment it came from, and the organization. The same reference adds once, and the same reference for another amount is refused, so a billing service may send a payment again. Today only whoever runs the server may add credits, from the server's own computer (`glave credits add`); the billing service calls the same operation with a sign-in of its own when it comes.
- **What each caller sees:** an organization's Owners and Admins, its balance, limit and spending this month, and each person's; anyone else, their own spending this month. Only an Owner sets the limit. The server says amounts; a client formats them.
- **Read back from the store:** each server reads an organization's ledger once, then only what is new before each call, so servers on one store see each other's holds and charges and a restart loses only charges not yet written.
- **What a hold costs:** one append before the call, which also carries any charge this server has not written yet, after reading what is new (the read the call made already), and the charge's append after it, as before: one small write more per call, never one per token. Racing servers append in turn, each reading the others' events first (`glave_ports::stream::append_retrying`); the store's check that one writer takes each place in a stream (`invariants.md`, 2) is what keeps two from holding the last of a balance. Calls on one server take turns at an organization's ledger, a read and an append each, so they queue rather than race, and only servers race each other.
- **A hold lapses** an hour after it was made for every server but its own, which counts it until its call ends however long that is: a server that stopped mid-call lets go of what it held within the hour, and a call still running past it can take the balance below nothing by at most its own worst case, as a reported cost above its hold does. The lapse is read on each server's own clock against the hold's time on its maker's, so clocks apart by seconds move it by seconds. A hold whose append may have landed unseen, the store's answer lost or the call dropped meanwhile, is let go of by a charge of nothing naming it, written at once or with the organization's next call; it never waits for the lapse.
- **The five deployments** (`deployments.md`):
  1. *Laptop:* no `[credits]`, so nothing changes.
  2. *Own server:* the same, unless its owner turns them on for the people they invite.
  3. *Glave Cloud, personal:* `[credits]` on; the person is the Owner of their organization of one, sees its balance and sets its limit.
  4. *Glave Cloud, enterprise:* the same, its Owners and Admins seeing everyone's spending and each person their own.
  5. *Enterprise, self-hosted:* their own providers and contracts, so no credits unless their operator turns them on, as a budget the operator adds to.

## A person's filters

Decided by the owner, 2026-10-29: through OpenRouter, a person chooses who serves their models, and the server keeps their choice and applies it to every chat. The case that set it: "I want DeepSeek, but I don't want my data sent to China".

- **What they choose,** in their settings ledger (`filters.set`, `events.md`): the order the router prefers providers in (lowest price or fastest; unchosen, the router's own balance); the least precision a model's weights may be served at (8-bit or better, full only); the countries providers are based in; only providers that keep nothing of what they are sent; the most tokens may cost; providers to avoid; and for a model, one provider of its own, or its own order. `filters/get` and `filters/set` read and keep them, with what "Europe" means (the European Economic Area, Switzerland and the United Kingdom), so clients offer "US and Europe" from the server's list.
- **Based in** means the provider's home and every datacenter OpenRouter names for it are among the countries chosen. A provider whose home OpenRouter does not say fits no such filter; one whose datacenters it does not name is judged by its home, and `model/list` says they are unknown, never guessed.
- **Every call of their work keeps to them,** its judge, title, compaction and memory's tidy-up included: the gateway asks the host for the filters of the person whose work a call is before each call that says so and has a router among its targets, so no call path can leave them out, and keeps to them at each target. Filters glave cannot read, or a server not yet ready to read them, refuse the call; a call that is no one's work asks for none. They change nothing for a model no router serves. Memory's tidy-up of a ledger several people read keeps to the filters of the one whose save asked for it.
- **Sent as OpenRouter takes them,** beside what every call asks (`data_collection: "deny"`, `require_parameters`): what OpenRouter has no filter of its own for, where providers are based and the one chosen for a model, as `only`, the providers that fit by the router's catalog (by the model's endpoints where it lists them, else by each provider's home); and its own `quantizations`, `sort` (`price`, `throughput`), `zdr`, `max_price` and `ignore`, which OpenRouter checks against its current lists. Each router target carries what its catalog says of who serves its model, so the gateway works this out for the target, never the host.
- **Refused before it is sent** when the catalog shows no provider of the model fits ("no provider of … fits your filters: loosen them to use it"), when it does not say where the router's providers are based and the filters ask that ("glave can't tell where …'s providers are based"), and when the filters could not be read: a call never goes out past filters glave could not read. A provider chosen for a model that the filters hide is refused the same way, never swapped for another.
- **Said with each model:** `model/list` answers each caller with which of their filters hide each provider of each model (`hidden_by`: where it is based, its precision, what it keeps, its price, or that they avoid it), so a client draws what the filters leave and why the rest are hidden, never deciding it itself.
- **Only a router keeps to them:** where a router serves a model, a call they narrow goes only to targets that are routers, never to another service that serves the same model; where none serves it, they leave the call alone. One that asks only an order goes anywhere, the order sent only to a router.
- **The five deployments** (`deployments.md`): the same on each, since they are the person's: on a laptop or their own server, for their own OpenRouter account; on Glave Cloud, for Glave Cloud's; an enterprise whose models no router serves sees them change nothing.

## A server's floor

Decided by the owner, 2026-10-31: a person on Glave Cloud uses the Cloud's own OpenRouter account, whose owner must be sure their data never goes where the owner doesn't trust. So a server may set one floor for everyone it serves, `[router_floor]` in its own `config.toml`, never a project's: the countries providers may be based in, and whether they must keep nothing. Off unless it asks something, so a laptop and a person's own server see nothing new.

- **It only narrows.** A person's filters apply within it: countries both allow, and nothing kept if either asks. Countries they chose that the floor doesn't allow never widen it, and when none are left no provider fits and the call is refused, never sent anywhere. Everything else (precision, price, avoiding, an order, one provider chosen) stays the person's, and one provider chosen outside the floor is refused.
- **Every call, whoever's it is:** the gateway holds it, so a call with no person behind it keeps to it too. `data_collection: "deny"` stays on every call, floor or no floor.
- **It fails closed on what no one says.** A provider whose home OpenRouter does not say is out, and a catalog that doesn't say where providers are based is refused, as is a target only a router could vouch for that isn't one: a server with a floor sends nothing to a service it can't check, even where no router serves the model.
- **"Based in" is what it promises, not where the machines are.** Decided by the owner, 2026-10-31: a provider is judged by its home, and by each datacenter where OpenRouter names them. Most name none (42 of 61 US-based providers when this was written, Fireworks and Groq among them), and those are judged by their home alone, so a floor of `US` admits them though they could run anywhere. Asking every provider to name its datacenters would leave too few, so it is not offered. `only` is an allowlist from the catalog, so a provider it has not listed can't slip in; one that moved is allowed until the next listing says so.
- **Refused with a sentence:** "this server allows no provider of … : choose another model", or, where the person's filters narrow too, that none fits both.
- **Said with each model:** `model/list` marks a provider the floor rules out (`hidden_by`: `server`), so the picker hides it and says why in the same line as a person's own filters. No screen of its own.
- **The five deployments** (`deployments.md`):
  1. *Laptop:* no table, nothing changes.
  2. *Own server:* the same, unless its owner sets it for those they serve.
  3. *Glave Cloud, personal:* set on the cell, for every organization on it. A gap: a model on the Cloud's own machines, such as Hope, and people's own accounts once they are allowed here aren't routers, so a floor refuses them until each says where it is.
  4. *Glave Cloud, enterprise:* the same floor; an organization's own filters within it are a gap, not built.
  5. *Enterprise, self-hosted:* set it only if they reach providers through OpenRouter: a floor refuses a service that isn't a router, so an organization on its own contracts leaves it off.

## Metering

- Every call produces the content-free `model.responded` event, with usage, cost, the price list it was computed from, route and target, the target's service in a person's words, and the provider a router passed it on to (OpenRouter names it in each chunk). A turn's receipt says where it ran from these ("via OpenRouter (Anthropic)") and what it cost, from the service's own numbers where it reports them (OpenRouter's `usage.cost`). A model the server calls on its own computer (a local endpoint) is priced at nothing, so its calls report $0.00 as any other reports its cost, and no client guesses it. There is no separate spend database: cost reports are views over the log.
- Calls glave makes on its own (the judge, compaction summaries) are metered and attributed to the thread that caused them.
- Provider prompt caching is passed through and its savings recorded. A response cache is off by default.

## Media tools

Decided by the owner, 2026-11-12 (#1260), from an independent design that read every provider's capabilities first: the agent makes images, speech, sound, music and 3D models through tools of glave's own, the same on every deployment. A tool names what it does, never who does it, so the provider behind it can change without a thread or a model noticing. Threads keep calls by name and glave's own model is trained on them, so once a tool ships its name stays and its shape only grows: an argument added later is optional, and a result gains fields, never loses or renames one.

**Shared rules.**

- **A file argument** is a saved file the thread holds, `blob:<sha256>` (one it made, one the person added, one the gate kept), or a file on the thread's computer by its path, as `read` takes it; a Library asset's id later.
- **`quality`** is one enum on every tool that has it: `low` (seconds and cents, for trying ideas), `medium` (the default), `high` (slowest and dearest, for finals). The server's settings map each tier to a model and its settings; the interface never names a provider. An argument the tier's model can't honour moves the call to a model that can; when none can, the call is refused in one sentence.
- **A result is the files made**, each a saved file and its media type, as the model reads it: `{"files": [{"file": "blob:<sha256>", "media_type": "image/png"}]}`, each kept whole as the provider made it, sealed in the thread's blobs; audio entries add `duration_secs`. An image is also a `file` part after it, so a model that reads images sees what it made (the copy made fit to send, `session.md`, "Attachments") and a client draws it. When the Library lands, each entry gains `asset`, the Library item's id, beside `file`; nothing else changes. A failure is an error result in a sentence the model can act on.
- **Long jobs.** Every media call waits up to 4 minutes, then answers `{"job": <n>, "status": "running"}`, numbered per thread as commands in the background are. `media_job` (`job`, `wait_secs` default 240 and at most 600, `cancel`) waits again or cancels one, and with no `job` lists the thread's. Jobs outlive turns, at most 8 run at once in a thread, and none is retried, since each submission is billed; a job's hold lasts until it ends.

**Built now.**

| `image_generate` | An image from a description, one a call | `prompt` (at most 8,000 characters); optional `aspect_ratio` (`1:1`, `2:3`, `3:2`, `3:4`, `4:3`, `9:16`, `16:9` or `21:9`, default `1:1`: every default model makes these, and another model makes the nearest), `quality`, `references` (files, at most 8, cited in the prompt by their order), `transparent` (default false) |

**Paid as a model call is** ("Credits"): on a server that keeps credits, held before it is sent and charged after, to the thread's organization for the person whose work it is, each charge's kind `media`. A tool whose model no catalog prices is refused before it is sent. Where no credits are kept, the person's own account pays, and nothing is held.

- **Filters and the floor hold** as for a model call ("A person's filters", "A server's floor"): a call through a router keeps to them, its providers read from the router's catalog; one that can't be kept to them is refused, never sent past them.
- **They ask where `web_fetch` asks,** since they send words and images beyond the computer and spend money.
- **The five deployments** (`deployments.md`):

  2. *Own server:* the same.
  3. *Glave Cloud, personal:* through the server's own accounts, paid from the person's credits.
  4. *Glave Cloud, enterprise:* the same, from the organization's credits.
  5. *Enterprise, self-hosted:* through their own accounts in the server's settings; credits only where their operator turns them on.
