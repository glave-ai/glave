# Gateway

The single door out for model calls and remote tools: which model serves each purpose, with whose keys, within what budget, and what it cost; and the tools that reach the outside world (search, image generation, speech, an organization's own systems), each with credentials only the gateway holds. Runs inside glave, for a person and for an organization's server alike: glave has no gateway service of its own ("No service of its own").

The seam: the harness owns the tools that act on the computer and the rules for using any tool; the gateway owns everything that leaves for the outside world.

## One default seam

Decided by the owner, 2026-10-19 (#392): **OpenAI's API is the one default seam for models.** glave speaks Chat Completions to OpenRouter, OpenAI, Azure, Bedrock's and Vertex's compatible endpoints, and any server that copies them (Ollama, LM Studio, vLLM, an organization's own).

- **"Add a model" offers OpenRouter and any OpenAI-compatible server up front** (and OpenAI's own). A model's capabilities come from the service's model list ("Catalogs"), and its price from glave's price list where that names it, else from the same model list ("Prices"), so a new provider needs no code when it speaks the seam.
- **A native format is an exception that must justify itself:** only where the compatible path loses something material, such as prompt caching, reasoning sent back, or an enterprise route served no other way. Anthropic's Messages API is one today, for Claude on Bedrock and Vertex (served only that way) and a direct key; it stays an internal route, not offered to add, and is expected to go once the routes glave uses no longer need it.
- **No new native format** without that justification written here first.

## No service of its own

Decided by the owner, 2026-11-08 (#1318): **glave has no gateway service of its own.** A company that runs a gateway (LiteLLM and the like) connects glave to it as an OpenAI-compatible server; pointing other agents at a person's or an organization's glave is #317, after v0.1, on the one server.

## Routes

A **route** names a purpose and maps it to an ordered list of **targets** (provider, model, region, credential reference), each with what it can do (tools, reasoning, images, context size).

- Purposes are a stable public vocabulary: `main`, `judge`, `summary` (compaction), `subagent`, `title` (a thread's title, `session.md`), and later `voice.listen`, `voice.speak`. A purpose with no route uses `main`.
- Routes are choices (nearest wins) and the models they may name are constraints (`policy.md`).
- **Choices.** Besides its routes, the gateway may offer targets a thread may choose (`session.md`, "Choosing a model and permissions"): in-process, the judge's model when it is another, and each of `[[models]]`. A call whose purpose uses `main`'s route and that asks for a choice by its name or model goes to that target alone; a purpose with a route of its own keeps it, and a call asking for `main`'s first model, or for any model that is not a choice, goes by its route as before.
- `model.responded` records the route and the target that actually served each call, so fallback is auditable.

## Fallback

- **Capability-checked:** a target that cannot honour the request (no tools, a smaller context than the conversation) is skipped, never sent a degraded request.
- **Thread-sticky:** a conversation that holds a provider's opaque reasoning falls back only to targets that accept it. Otherwise the reasoning is stripped explicitly and that is recorded.
- **One provider per conversation at a router** (2026-11-15): each provider behind a router keeps its own prompt cache, so a conversation whose calls land on different providers misses it (Haiku through OpenRouter under Cloud's floor, spread over Bedrock and Vertex, read 60% of its input from cache against 81% on one provider, and cost 55% more). Every call that sends a thread's conversation (its turns', a subagent's, a compaction's summary) tells OpenRouter the thread's id as `session_id`, so its provider sticky routing keeps the conversation with the provider that first served it, from that first answer on, and falls back when that one fails (OpenRouter's prompt caching docs, "Provider Sticky Routing"; `session_id` in its chat completions request). It chooses only among the providers the call's preferences allow, and glave sends no `provider.order`, which would turn it off. The judge's and a title's calls send prompts of their own and no session. The id is the thread's opaque UUID, nothing of the person's; the prompt is sent exactly as it would be (invariant 27).
- **Reasoning goes back on the current turn alone** (#945): on the compatible route a model's reasoning goes back on the assistant messages after the person's last message, so it keeps its chain across tool calls as Codex's chat route did; earlier turns' is dropped, as it only cost tokens without a gain in the evals, except where the model's maker wants every turn's, at any service ("Decoding"). It goes in the field it came in (`reasoning_content`, `reasoning`), or as OpenRouter's `reasoning_details`, kept exactly, signatures and encrypted entries included, and only to the provider and model that produced it. A server that never streams reasoning is sent no new field.
- Failures that may pass (rate limits, overload, timeouts) move to the next target after the provider's own retries. Never once output has come: an answer that breaks off partway goes to the caller as it is, since asking again, here or in the harness, would paste a second answer after the first's start.

## A bounded answer

Every call asks for an answer no longer than its request does (a turn's, 32,000 tokens, as OpenCode caps it), nor than its target's catalog says the model gives, nor than the window has room for after the input (at least 1,024), so an answer that never ends stops (#1435). With nothing known of the model, a turn's cap is not sent, as it may not fit. The harness also stops an answer that repeats itself as it streams.

## Catalogs

What a model can do is the provider's to say, never glave's: its context window, longest answer, whether it reads images and the levels of reasoning effort it offers come from the service's own model list, read the same way from every service (OpenRouter's `GET /api/v1/models` says all of it, Anthropic's `GET /v1/models` its effort levels, vLLM its context, most services little beyond the id). So does its price, where glave's price list doesn't name the model at that service ("Prices"). Nothing about a model is written into glave's code but what its maker documents for calls to it and no catalog carries ("Decoding"), and glave's price list, a file of data the owner decided glave keeps (2026-11-15), since the makers' own lists carry no prices.

- **Kept in the store**, never in a cache server of its own: one catalog per service a person connected (its kind, and its URL for another server), each with when it was listed and its models as the list described them, in the catalog ledger (`events.md`). Only the latest `catalog.refreshed` is read.
- **A server's own OpenRouter has a catalog too:** when the endpoint a server's settings choose is OpenRouter itself, as on Glave Cloud, it is read and offered as a person's account is, with the server's key, and its catalog kept beside theirs. No one connected it, so it is never kept as an account or listed as anyone's. On a server that keeps credits it offers every model its catalog lists, unless the settings name the models to offer (`[[models]]`), then those, the main model and the judge's; elsewhere only those, so choosing one model in the settings never offers everyone the rest on the server's key. Until its first listing its main model has no price, so a server that keeps credits refuses its calls for that moment; `model/list` and every turn start that listing.
- **Listed when an account is added**, by the call that checks its key; **daily**, when the server is next asked for its models or starts a turn after a catalog grew a day old, in a task no one waits for; and **on demand** (`provider/refresh`). A service that cannot be reached keeps its catalog and is tried again an hour later; one that answers the same is not written again.
- **A router's endpoints:** OpenRouter serves most models from several providers, each with its own precision, context, price, speed and data policy. Its catalog keeps, beside the models, OpenRouter's providers (`GET /api/v1/providers`: each one's slug, name, the country it is based in and the countries of its datacenters, where OpenRouter says them; datacenters it does not name are unknown, never guessed), and each model's endpoints (`GET /api/v1/models/{id}/endpoints`: its provider, how its weights are stored, its context, longest answer, price and median speed over OpenRouter's last half hour), each marked as keeping nothing where OpenRouter lists it so (`GET /api/v1/endpoints/zdr`); an endpoint that takes no tools is left out, since glave's calls may use them. They are read when the catalog is listed, a few models at a time, all within two minutes. When the providers or the endpoints that keep nothing cannot be read, the catalog keeps what it had and is listed again an hour later, as nothing of a model's would be known; a model whose own endpoints are not read keeps those it had, and when the two minutes ran out first, the catalog is listed again an hour later too. A median speed changes with every listing, so a catalog whose speeds alone changed is not written again. Adding an account lists its models alone, so it stays quick, and the refresh it makes due reads the rest. `model/list` says each model's endpoints with where each provider is based, so a client can filter by them; the precision is glave's reading of OpenRouter's name for how the weights are stored (four, six or eight bits, full, or unstated).
- **A router's image models:** OpenRouter serves its image models through its image API, apart from its chat models. The ones the image tiers name ("Media tools") are read when the catalog is listed, each one's providers with what they bill (`GET /api/v1/images/models/{id}/endpoints`: a line for each thing billed, text and images in and images out, by the token or the image, some by a variant), within two minutes of their own, and kept in it beside its chat models, never offered as one. A provider is priced by the token at the dearest of its lines for each part; one that bills anything otherwise (by the image or the megapixel), or can't be read, leaves its model with no price; a model has one only when every provider of it does, at the dearest of theirs, so a call's hold never falls short of where it may go. Its providers are what filters by country choose among. A model not read keeps what the catalog had of it, and the catalog is listed again an hour later.
- **An account's models are its service's catalog's**, those glave can talk with, newest first, at most a thousand: a model the service adds shows up from the next refresh, with no new glave and no reconnecting.

## One entry per model

The same model can be reached at several services (Claude Haiku from Anthropic or through OpenRouter, GPT from OpenAI or OpenRouter, an open model from OpenRouter or a person's own server). A person chooses the model; glave chooses the route (#289).

- **One name across services:** the id without its maker's prefix, in lower case, dots as hyphens, without a date at its end, so `claude-haiku-5-5-20261007` and `anthropic/claude-haiku-5.5` are one model. Ids that differ more show once per service.
- **Route order:** the settings' model (an organization's cloud contract) first, then the maker's own API (OpenAI, Anthropic), then an aggregator (OpenRouter), then any other server. A later service serves only when the one before fails in a way that may pass, by the fallback above; the entry's `id` is the first service's.
- **What `model/list` says of it** comes from the catalogs: its own name and maker (OpenRouter's `Anthropic: Claude Haiku 5.5`; a name the settings give over it, which may name its maker the same way), and where neither names it, the server writes them from its id as its maker would (`openai/gpt-6-luna` is OpenAI's `GPT-6 Luna`), so every entry has a name and no client names a model from its id; the services in that order, its context, longest answer, images and reasoning levels from its first service's catalog, else from another's for the same model (the levels its first target is sent, where that target has some of its own, as a cloud contract's Claude does with no catalog), and its price ("Prices") and the level it is sent unasked at the first service alone, since that is where a call goes. The gateway checks requests against the same context and images, holds credits at that price, and records the price list it came from (`glave 2026-11-23`, `openrouter catalog 2026-11-22`) when the provider reports no cost of its own.

## Prices

Decided by the owner, 2026-11-15 (#1625): Glave Cloud goes direct to Western model makers, Anthropic, OpenAI, Google and DeepInfra, and stops taking its models from OpenRouter: vendors a business can rely on, not a router's long tail of hosts. And glave keeps its own price list rather than relying on others for what people are charged. Anthropic's, OpenAI's and Google's model lists carry no prices, and credits refuse a call they can't price ("Credits"), so glave writes the prices down, in one file, kept current by a weekly watch, and set otherwise by whoever pays the provider. The list holds the makers' own prices, whatever Glave Cloud may add on top: its revenue model is still under discussion, and the option on the table is a fee on credit purchases (owner, 2026-11-24). Decided by the owner too, 2026-11-23: Glave Cloud launches with all four makers, each on an account of its own, and drops OpenRouter entirely, its image tools going direct through its OpenAI and Google accounts ("Media tools").

- **One file, beside the gateway:** `crates/gateway/prices.toml`, built into glave and versioned with it, never fetched, as glave's catalog of connectors is (`session.md`, "Connectors"). It is TOML, as the repository's other data people edit is: an entry can carry a comment saying why its price is what it is, and a person reads its changes line by line. Prices are written as decimal text and read exactly into nanos (`events.md`, "Money"), never through a float, so the list's precision is a billionth of a dollar per million tokens. The list's name is the latest of its entries' dates: `glave 2026-11-23`.
- **An entry** is a service and a model. The service is named as receipts name it: `anthropic`, `openai`, or another server's host, such as the Gemini API's `generativelanguage.googleapis.com` and DeepInfra's `api.deepinfra.com`. The model is keyed by its own id as that service's API names it: `claude-haiku-5-5` at `anthropic`, `deepseek-ai/DeepSeek-V4.1-Flash-1017` at DeepInfra. "One entry per model" maps one model's ids across services, so the file never does. A service that serves no model names `search` in the model's place: Brave's, at `api.search.brave.com` ("Web search"). An entry holds what a use costs there, in US dollars:
  - input and output, per million tokens;
  - cache reads and cache writes, where the maker bills them apart: Anthropic's writes at 1.25 times input, for the five-minute cache glave asks for;
  - reasoning and images in, only where billed apart from output and text;
  - for an image model, images out: a price per image made, at the size its tier asks for, or per image token where the maker bills that way (GPT Image);
  - a higher price for a call whose prompt is longer than a length its maker names, on every token of that call, as the makers bill it (Claude Haiku 5.5 above 100,000 tokens, GPT-6 Luna above 272,000);
  - a price per request, where there is one.

  An entry with a price per request needs no token prices, as a search has no tokens; any other has input and output. An entry also holds its date and its maker's page. Its date is the day its price last changed, as a person checked it against that page then. It holds nothing about what the model can do, which stays its catalog's.
- **Which price a call has,** nearest first: the settings of whoever pays the provider; then glave's list, where it names the model at that service; then the service's own catalog; else none. The list wins over a catalog because what people are charged then changes only after a person has checked it, never because of a third party's listing at run time. It names only the services Glave Cloud pays directly, so a model at OpenRouter keeps its catalog's price, and nothing changes for a person's own OpenRouter. What a call costs is still its provider's reported cost where it reports one ("Credits"). The price holds the call before it is sent, and charges it where no cost is reported. None of the four makers reports one.
- **Set by whoever pays the provider:** entries of the same shape in the person's or the server's own `config.toml` (`[[prices]]`), each replacing glave's for its service and model, or adding one. A project's never sets them, since a repository pays no provider. A server's owner sets them for a negotiated rate, for a cloud contract, or at once when a maker changes a price before a release of glave carries it. A price is recorded as `the server's settings` when these set it. An organization's own keys on Glave Cloud, and its prices with them, wait until such keys are allowed there (`deployments.md`, Models): a gap.
- **Watched nightly, hands-off** (owner, 2026-11-24): `cargo xtask prices`, nightly and by hand (`prices.yml`), never on a pull request or in the merge queue, as the connectors' check is (`connectors.yml`), so a vendor's bad day never holds up a merge. It reads public lists only, with no key. For DeepInfra, its own (`GET https://api.deepinfra.com/models/list`, each model's price per token). For the makers that publish prices only as a web page, two open lists that track those pages, Pydantic's genai-prices and LiteLLM's (both MIT), and OpenRouter's public model list, which charges the makers' own prices for their models. For DeepInfra it writes the price DeepInfra's own list says. For Anthropic, OpenAI and Google it writes a price only where at least two of the three sources agree. Each source's price is rounded to the list's precision before they are compared, since LiteLLM's are floats in dollars per token. Each price it writes is dated as any entry is: the day its price last changed. It names, without writing them, any disagreement, any model of these makers the sources list and the file lacks, and any entry no source lists any more, for a person to settle from the maker's page. It opens a pull request only when a price changed: one, on one branch, saying each change, the sources that said it and the maker's page, which the agent working the queue opens, checks against that page and handles. No change, no pull request: a night with no change leaves the file alone. A price it can't find or confirm never fails the run: it keeps one issue updated with what it couldn't, as `connectors.yml` keeps its one issue. The owner hears only when a maker raises a price by more than a fifth.
- **Said with each model:** `model/list` says each model's price and the price list it is from. The file in this public repository is the list for anyone to read. A public page of Glave Cloud's prices comes when Glave Cloud opens to strangers, not before (owner, 2026-11-24), and a copy as JSON waits for it.
- **What a charge says:** `model.responded` records the price list of each cost it computed, as it does today (`glave 2026-11-23`, `the server's settings`, `openrouter catalog 2026-11-22`, `openrouter:reported`). A charge in the credits ledger names none: that waits for the billing service, which may need its ledger alone to say at what price each call was charged.
- **A model with no price** (none in the settings, none in the list for its service, none in its catalog) is not offered by `model/list` on a server that keeps credits, and is refused there when asked for by name, as today. Elsewhere it is offered, and its receipts say no cost, as today. A model Glave Cloud serves on its own machines, such as Hope, has no list price, so it needs one in Cloud's settings to be offered where credits are kept.
- **The direct routes are glave's own adapters.** Anthropic through its Messages API (`glave-provider-anthropic`, the one native exception, kept for its prompt caching and signed thinking, "One default seam"). OpenAI through Chat Completions at `api.openai.com` (`glave-provider-openai`). DeepInfra through its OpenAI-compatible endpoint, `https://api.deepinfra.com/v1/openai` (`glave-provider-openai`). Google through the Gemini API's OpenAI-compatible endpoint with a key (`glave-provider-openai`; owner, 2026-11-24), serving no one until evals pass, sending back each thought signature as it came, since Gemini's function calling refuses a later turn without them. Each is one of the server's own accounts, its key only in the server's environment, read and offered as a person's account is, several at once, as the server's own OpenRouter is today (#1120). Each conversation then stays with one provider's cache by itself ("Fallback"). OpenAI and Anthropic are told whose call it is, which OpenRouter never was ("Whose call it is"). Images go through the same two accounts and the media port's `make`, as OpenRouter's image API does today (#1382), in `glave-provider-openai`:
  - OpenAI's Images API: `POST /v1/images/generations`, and `/v1/images/edits` for an edit or references, `background: "transparent"` for a transparent call. It is priced by the image tokens its answer reports, in and out, at the list's prices.
  - The Gemini API's OpenAI-compatible `images/generations`, which takes a prompt alone. So a call with references or an edit moves to OpenAI's model, as any argument a tier's model can't honour does ("Media tools"). It is priced by the tokens its answer reports, else per image made, from the list. Like Google's chat route, it serves no one until evals pass.
- **What it replaces:** Glave Cloud's own OpenRouter as its source of models. With it goes Glave Cloud's floor (`[router_floor]`), which would refuse every service that isn't a router ("A server's floor"); the four makers are its floor now. The floor's code is removed only once Glave Cloud stops using OpenRouter, its one user (owner, 2026-11-24). Brave's price for a search, written beside its adapter today, moves into the list as a price per request ("Web search"), so every price glave charges at is in one file. OpenRouter stays fully supported for anyone who connects their own account, on a laptop or their own server, with their own filters ("A person's filters"), and for any server whose settings choose it; Glave Cloud uses it for nothing, its image tools included.
- **What the makers' lists don't say:** going direct, a model's context and longest answer come from its maker's list, and OpenAI's says neither, where OpenRouter's said both. That gap is not the price list's, which holds prices only (#540).
- **The five deployments** (`deployments.md`):
  1. *Laptop:* the list is built in, so a person's own key at Anthropic, OpenAI, Google or DeepInfra gets receipts saying what each turn cost at its maker's price, where today they say none. Their own OpenRouter keeps its catalog's prices and reported cost, and their own `config.toml` may set a price of theirs. Nothing new to click.
  2. *Own server:* the same; its owner pays.
  3. *Glave Cloud, personal:* its own accounts at the four makers, its image tools' too, every call held and charged at the price its settings set, else the list's, and only priced models offered.
  4. *Glave Cloud, enterprise:* the same; an organization's own keys and prices there are a gap, as above.
  5. *Enterprise, self-hosted:* their cloud contracts (Azure, Bedrock, Vertex) are priced in their own settings where their operator keeps credits, since the list holds no cloud's prices until someone needs them; a maker's API they reach directly is priced by the list.

## Reasoning effort

Decided by the owner, 2026-10-24 (#703): when a model's default level is known, glave sends it explicitly, rather than leave it to whichever provider serves the call, and shows it; when no catalog says it, glave sends none, and a client says the model reasons by its maker's default.

- **Known only from a catalog.** OpenRouter's listing says the level reasoning starts at (`default_effort`) and whether the model reasons unasked (`default_enabled`, `mandatory`), so the level it uses unasked is that one when it reasons unasked, `none` when it does not (or its `default_effort` is `none`), and unknown when the listing does not say. Nothing about a model is written into glave.
- **Each target's own catalog, never another service's.** OpenRouter's level names are its own, each mapped to the nearest one the provider behind it takes; OpenAI's API takes its own levels for each model, refuses others and defaults differently. A target whose catalog names no levels, such as OpenAI's own API, is sent none, even when another service's catalog for the same model names a default; sending one would guess. So is a target with no catalog at all, a cloud contract's (`[provider]`), but for Claude (below).
- **Claude** (#708; Anthropic's docs read 2026-10-25: effort, thinking, the model list). A level goes as `output_config.effort` with `thinking: {"type": "adaptive"}`, so it sets how much the model thinks. Later models think adaptively unasked, so on them asking for their default level is the same as asking for none; Claude Opus 4.6 to 4.8 and Sonnet 4.6 think only when asked, so there a level turns thinking on and none leaves it off. The levels offered are those Anthropic's model list marks supported (`capabilities.effort`) on a model that takes adaptive thinking. One the list says takes no level, or only extended thinking (4.5 and earlier, which refuse `adaptive`), is offered none, whatever another service offers for it. Bedrock and Vertex AI list no models this way, and a key set in the settings has no catalog, so Claude there is offered the five levels Anthropic documents (`max`, `xhigh`, `high`, `medium`, `low`); a model that does not take the one picked refuses it, and the person sees the API's own message. Anthropic's list names no default, so a thread that chooses none is sent none.
- **The gateway applies it**, from the target, so every caller through it gets the same: on every call of every purpose, a level asked for that the target offers, else its model's default, else none. The person's pick wins wherever it can be sent. The default is the level the service's catalog names as the model's own, so a call that asks for none, the judge's and titles' among them, is sent that level.
- **What is sent is said:** `model/list`'s `reasoning.default` is the level a thread that chooses none is sent at the model's first service, absent when glave sends none; `model.responded` records the level each call was sent with (`effort`).

## Decoding

Decided by the owner, 2026-11-15 (#1440): a model is sent its maker's documented decoding on every call, rather than left to each host's defaults, which differ for the same open weights. One table in the compatible provider (`maker.rs`) holds it by family, matched by the model's id at any service; it never changes the prompt, only the request's parameters.

- **The maker's sampler, never a penalty.** Each model is sent the values its own card gives: DeepSeek V3.2 and V4.1 Flash `temperature` 1.0 and `top_p` 0.95, the values their agentic evaluations ran at; V4 Flash and V4 Pro 1.0 and 1.0; an alias (`deepseek-flash`, OpenRouter's `~deepseek/deepseek-pro-latest`) those of the model it names today. A release whose card gives none, such as V3.2's experimental one, is sent none. Anthropic's and OpenAI's models, and any model whose maker documents nothing, are sent none. No repetition, frequency or presence penalty is ever sent: none is the maker's. DeepSeek's own API ignores the sampler while its model thinks, so there it changes nothing.
- **Every turn's reasoning, where the maker wants it.** DeepSeek's thinking mode refuses a request with tools unless every earlier assistant message carries `reasoning_content`, so every assistant message to a DeepSeek model from V3.2 on carries it, at any service, empty where the message has none of that model's; OpenRouter reads `reasoning_content` as its own `reasoning`. Earlier DeepSeek models (V3.1, R1 and the models distilled from it) take no tools while thinking and are sent only the current turn's, as any model is. The same history is sent byte for byte on every call, so the cache holds.
- **Not yet:** a model known only by a name its account gives it, such as an Azure deployment's, matches no family, so it is sent neither.

## Keys

- The gateway resolves credentials; nothing that calls it ever holds them.
- **Sources:** the OS keychain for a person; environment, a KMS, a secrets manager or workload identity for an organization; short-lived tokens refreshed outside the request path.
- **Cloud contracts are targets like any other:** Amazon Bedrock, Azure OpenAI, Google Vertex, and the company's own vLLM. That is how "data on our servers, models through our cloud contract" works (below).
- **How a provider is reached** (`glave_ports::auth::Auth`): nothing (a local server), a fixed key in the header the provider wants (`Authorization: Bearer`, Azure's `api-key`, Anthropic's `x-api-key`), or credentials that change: each request asks them for its headers, so one interface carries a bearer token refreshed before it expires (Entra, later Google) and a signature over each request (AWS SigV4). Credentials are kept until five minutes before they expire, and fetched outside any lock. A failure to get them is refused (`ProviderError::Credentials`) or, when the source could not be reached, passing.
- Keys and tokens never show: not in `Debug`, logs, errors or answers; header values are marked sensitive.

Each model is reached through the cloud's OpenAI-compatible Chat Completions, so the requests are the ones glave sends any such server, except Claude on Bedrock and Vertex, which those clouds serve only through Anthropic's Messages API. ## Budgets

- **No budget is kept today.** An organization's spending is held by its credits ("Credits", below); the per-person daily budget went with the gateway service (#1318).
- **A person's monthly budget (#662) and the others** (an organization's, a project's, a thread's within the threads above it, a worker's, limits in tokens) **wait for the first organization that needs them.** Each will be held and settled as credits are, and read back from the log after a restart.
- **Exact, and never past the limit of what can be counted.** A hold and a cost are nanos. A cost rounds up to the next nano, so a call that cost anything never counts as free. A sum that would not fit in 64 bits stops at the most there can be.

## Credits

Decided by the owner, 2026-10-29: on Glave Cloud people use Glave Cloud's own models and key, and pay for what they use. No subscription and no base fee: an organization pays ahead for credits in US dollars, bought by card. Model calls are charged at cost, the provider's own reported cost (OpenRouter's `usage.cost`), with no markup. Each organization has a monthly spending limit, about $10 unless its Owner raises it. Compute, disk and other infrastructure are charged later, at a markup. Card payments and topping up on their own come later, through Polar, from a billing service of their own that calls glave's admin API. Going direct to the makers (owner, 2026-11-15), whose answers report no cost, a call is charged at its price, from the server's settings or glave's price list ("Prices"). Built by #1054:

- **Only where the server's own configuration says so** (`[credits]` in its `config.toml`, never a project's): `monthly_limit_usd`, the limit each organization starts with, is the server's own number, as no limit is written into glave. Without the table nothing changes: no balance, no refusal, nothing new to see or click (principle 4).
- **The credits ledger** is one stream of the organization's own, beside its people ledger (`events.md`): money added, the limit its Owner set, and each charge with its kind of cost (`model`, `media` for the media tools, `search` for web searches, so compute and disk join the same balance later) and whose work it was. The balance is everything added less everything charged; the month's spending, everything charged since the month began in UTC. Amounts are exact, in nanos, billionths of a dollar (`events.md`, "Money"); cents are only for showing them.
- **Reserve, then settle, against both.** Before a call is sent, its worst case at its target's price is held (what it reads, estimated cautiously, each image sent inline at 1,600 tokens, or 8,192 to an image model, and each PDF by its size as if it were text but at most twenty pages of 1,500 tokens, since its pages can't be counted without reading it whole, never more than the target's window holds; and the longest answer it may be sent) against what calls running leave free of the balance and of the month's limit, on every server on the store: the hold is a `credits.held` in the ledger, appended only once everything before it was read, so of servers racing for the last of a balance one holds it and the others read its hold before they hold. It is refused before it is sent, with a sentence a person acts on (`-32020`, `failure: over_budget`): when nothing is left of the balance ("your balance is used up: ask whoever runs this server to add more", since only they add to it until payments come), even for a call priced at nothing; when the month's limit is spent ("this month's spending limit of $10.00 is reached"); or when its worst case is more than what is free now, saying both, what it needs rounded up to the cent and what is free rounded down. A model with no price is refused too, since no one can say what its call could cost, and the next target that has a price serves it instead. On a server that keeps credits, its models are the makers', reached through its own accounts and priced by its settings, else by glave's price list ("Prices"). Until that is built they are its own OpenRouter's, priced by its catalog. `model/list` still offers one with no price: a gap, closed with the price list, which offers none there.
- **What a call costs** is its provider's reported cost in dollars, else its usage at its price, counted in this server's book at once in its hold's place, and written to the store after, its `credits.charged` naming the hold it lets go of for every server, each charge with the id it was first written with, so one whose append landed unseen is read back in its count's place, never written twice; one the store does not take stays counted and is written with the next. A call cancelled once sent is charged what it read (its files counted as its hold counts them, but each image at 1,600 tokens, and never more than the window holds) and what came of its answer, text, reasoning and a tool call's arguments as they stream, at its price, as its provider charges for them; one that broke off, or went unanswered once sent (silence, a broken connection, an answer that can't be read), the same, since its provider billed what it read; one its provider refused with an error, before its answer or inside it with nothing yet, one that could not be written out, or one that never reached it (no connection opened: its name not found, the connection refused), nothing. An answer that reports nothing it used, neither a cost nor a token, is charged the same way as one cut short, never nothing, and its receipt says no cost; one whose usage is estimated, from a stream that ended before its provider said all of it, at what it says it read, at its cache's prices, and no less of its answer than came. A reported cost below nothing is not believed: the call is charged its usage at its price. A reported cost above the hold takes the balance below nothing, by that much.
- **Charged no less than billed** (#1659): an answer that reports no usage, or usage estimated from a stream that ended early, is charged at least what it read and what came (a media call, its hold); a call sent and left unanswered, what it read; one refused or that never reached its provider, nothing. A tool call's arguments count as they stream, a reported cost below nothing is refused, and inline images and PDFs are held and charged at what they may read.
- **Who pays:** every call a thread makes, its judge, title and compaction summaries included, is charged to the thread's organization for the person it works for; memory's tidy-up for the person whose memory it tidies. A call no organization asked for is charged to no one.
- **Adding credits** is one admin operation: an amount, the reference of the payment it came from, and the organization. The same reference adds once, and the same reference for another amount is refused, so a billing service may send a payment again. Today only whoever runs the server may add credits, from the server's own computer (`glave credits add`), and lists the personal spaces sign-ups made with their balances to find one (`glave credits list`); a sign-up link they make may carry what its space starts with (`glave signup link --credits`), added as the space is made, its link its payment's reference. The billing service calls the same operation with a sign-in of its own when it comes.
- **What each caller sees:** an organization's Owners and Admins, its balance, limit and spending this month, and each person's; anyone else, their own spending this month. Only an Owner sets the limit. The server says amounts; a client formats them. Whatever a person sees says "balance" and dollars, never "credits" (owner, 2026-11-14).
- **Read back from the store:** each server reads an organization's ledger once, then only what is new before each call, so servers on one store see each other's holds and charges and a restart loses only charges not yet written.
- **What a hold costs:** one append before the call, which also carries any charge this server has not written yet, after reading what is new (the read the call made already), and the charge's append after it, as before: one small write more per call, never one per token. Racing servers append in turn, each reading the others' events first (`glave_ports::stream::append_retrying`); the store's check that one writer takes each place in a stream (`invariants.md`, 2) is what keeps two from holding the last of a balance. Calls on one server take turns at an organization's ledger, a read and an append each, so they queue rather than race, and only servers race each other.
- **A hold lapses** an hour after it was made for every server but its own, which counts it until its call ends however long that is: a server that stopped mid-call lets go of what it held within the hour, and a call still running past it can take the balance below nothing by at most its own worst case, as a reported cost above its hold does. The lapse is read on each server's own clock against the hold's time on its maker's, so clocks apart by seconds move it by seconds. A hold whose append may have landed unseen, the store's answer lost or the call dropped meanwhile, is let go of by a charge of nothing naming it, written at once or with the organization's next call; it never waits for the lapse.
- **The five deployments** (`deployments.md`):
  1. *Laptop:* no `[credits]`, so nothing changes.
  2. *Own server:* the same: it serves its owner alone (owner decision, 2026-11-16), so there is no one else's spending to hold.
  3. *Glave Cloud, personal:* `[credits]` on; the person is the Owner of their organization of one, sees its balance and sets its limit.
  4. *Glave Cloud, enterprise:* the same, its Owners and Admins seeing everyone's spending and each person their own.
  5. *Enterprise, self-hosted:* their own providers and contracts, so no credits unless their operator turns them on, as a budget the operator adds to.

## A person's filters

Decided by the owner, 2026-10-29: through OpenRouter, a person chooses who serves their models, and the server keeps their choice and applies it to every chat. The case that set it: "I want DeepSeek, but I don't want my data sent to China".

- **What they choose,** in their settings ledger (`filters.set`, `events.md`): the order the router prefers providers in (lowest price or fastest; unchosen, the router's own balance); the least precision a model's weights may be served at (8-bit or better, full only); the countries providers are based in; only providers that keep nothing of what they are sent; the most tokens may cost; providers to avoid; and for a model, one provider of its own, or its own order. `filters/get` and `filters/set` read and keep them, with what "Europe" means (the European Economic Area, Switzerland and the United Kingdom), so clients offer "US and Europe" from the server's list.
- **Based in** means the provider's home and every datacenter OpenRouter names for it are among the countries chosen. A provider whose home OpenRouter does not say fits no such filter; one whose datacenters it does not name is judged by its home, and `model/list` says they are unknown, never guessed.
- **Every call of their work keeps to them,** its judge, title, compaction and memory's tidy-up included: the gateway asks the host for the filters of the person whose work a call is before each call that says so and has a router among its targets, so no call path can leave them out, and keeps to them at each target. Filters glave cannot read, or a server not yet ready to read them, refuse the call; a call that is no one's work asks for none. They change nothing for a model no router serves. Memory's tidy-up of a ledger several people read keeps to the filters of the one whose save asked for it.
- **Sent as OpenRouter takes them,** beside what every call asks (`data_collection: "deny"`, `require_parameters`): what OpenRouter has no filter of its own for, where providers are based and the one chosen for a model, as `only`, the providers that fit by the router's catalog (by the model's endpoints where it lists them, else by each provider's home); and its own `quantizations`, `sort` (`price`, `throughput`), `zdr`, `max_price` and `ignore`, which OpenRouter checks against its current lists. Each router target carries what its catalog says of who serves its model, so the gateway works this out for the target, never the host.
- **Refused before it is sent** when the catalog shows no provider of the model fits ("no provider of … fits your filters: loosen them to use it"), when it does not say where the router's providers are based and the filters ask that ("glave can't tell where …'s providers are based"), and when the filters could not be read: a call never goes out past filters glave could not read. A provider chosen for a model that the filters hide is refused the same way, never swapped for another.
- **Said with each model:** `model/list` answers each caller with which of their filters hide each provider of each model (`hidden_by`: where it is based, its precision, what it keeps, its price, or that they avoid it), so a client draws what the filters leave and why the rest are hidden, never deciding it itself.
- **Only a router keeps to them:** where a router serves a model, a call they narrow goes only to targets that are routers, never to another service that serves the same model; where none serves it, they leave the call alone. One that asks only an order goes anywhere, the order sent only to a router.
- **The five deployments** (`deployments.md`): the same on each, since they are the person's: on a laptop or their own server, for their own OpenRouter account; on Glave Cloud, for Glave Cloud's; an enterprise whose models no router serves sees them change nothing.

## A server's floor

Decided by the owner, 2026-10-31: a person on Glave Cloud uses the Cloud's own OpenRouter account, whose owner must be sure their data never goes where the owner doesn't trust. So a server may set one floor for everyone it serves, `[router_floor]` in its own `config.toml`, never a project's: the countries providers may be based in, whether they must keep nothing, and the least precision they may serve a model's weights at (owner, 2026-11-15: `precision = "fp8"` admits 8 bits and better, by OpenRouter's names, `policy.md`). Off unless it asks something, so a laptop and a person's own server see nothing new.

- **A misspelling is an error:** a name glave doesn't know, an empty list of countries, or a country that isn't two capital letters, since a floor a misspelling turned off would keep nothing out.
- **It only narrows.** A person's filters apply within it: countries both allow, nothing kept if either asks, and the higher precision of the two. Countries they chose that the floor doesn't allow never widen it, and when none are left no provider fits and the call is refused, never sent anywhere. Everything else (price, avoiding, an order, one provider chosen) stays the person's, and one provider chosen outside the floor is refused.
- **Its precision is decided per model.** Decided by the owner, 2026-11-15: the floor must not omit the closed models, whose makers (Anthropic, OpenAI, and the clouds that resell them) tell OpenRouter nothing of how they store the weights (`unknown`). So a model none of whose endpoints in the catalog says its precision is closed, and the floor's precision does not apply to it: it is sent no `quantizations`. Any model one of whose endpoints says its precision is held to it, and its providers that say none are out, since an open model's unsaid endpoints may serve fewer bits (when this was written, 22 of DeepSeek V4.1 Flash's 49 said `unknown`, some known to serve 4 bits): OpenRouter is sent the names at the minimum and above, never `unknown`. A model whose endpoints the catalog doesn't list is held to it too. A person who chooses a precision of their own chooses providers that say theirs, as their filter always has, so for them a closed model's providers are hidden by their own filter.
- **Every call, whoever's it is:** the gateway holds it, so a call with no person behind it keeps to it too. `data_collection: "deny"` stays on every call, floor or no floor.
- **It fails closed on what no one says.** A provider whose home OpenRouter does not say is out, and a catalog that doesn't say where providers are based is refused, as is a target only a router could vouch for that isn't one: a server with a floor sends nothing to a service it can't check, even where no router serves the model.
- **"Based in" is what it promises, not where the machines are.** Decided by the owner, 2026-10-31: a provider is judged by its home, and by each datacenter where OpenRouter names them. Most name none (42 of 61 US-based providers when this was written, Fireworks and Groq among them), and those are judged by their home alone, so a floor of `US` admits them though they could run anywhere. Asking every provider to name its datacenters would leave too few, so it is not offered. `only` is an allowlist from the catalog, so a provider it has not listed can't slip in; one that moved is allowed until the next listing says so.
- **Refused with a sentence:** "this server allows no provider of … : choose another model", or, where the person's filters narrow too, that none fits both.
- **Said with each model:** `model/list` marks a provider the floor rules out, by where it is based, what it keeps or the precision it says (`hidden_by`: `server`), so the picker hides it and says why in the same line as a person's own filters. No screen of its own.
- **The five deployments** (`deployments.md`):
  1. *Laptop:* no table, nothing changes.
  2. *Own server:* the same, unless its owner sets it for those they serve.
  3. *Glave Cloud, personal:* set on the cell, for every organization on it, while its models come through its OpenRouter. Going direct to the makers ("Prices"), it sets none, since a floor refuses every service that isn't a router. A gap: a model on the Cloud's own machines, such as Hope, and people's own accounts once they are allowed here aren't routers, so a floor refuses them until each says where it is.
  4. *Glave Cloud, enterprise:* the same floor; an organization's own filters within it are a gap, not built.
  5. *Enterprise, self-hosted:* set it only if they reach providers through OpenRouter: a floor refuses a service that isn't a router, so an organization on its own contracts leaves it off.

## Whose call it is

Decided by the owner, 2026-11-15: a model's maker that finds its policy broken should be able to act on the one person who broke it, not suspend the account everyone's calls go through, as their best practice asks. So each call that works for a person tells its provider who, by an id that says nothing of them.

- **The id:** `g_` and 32 hex digits, the first 128 bits of an HMAC-SHA-256 of the organization's id and the person's under a secret the server's root derives (`crates/keys`, `Root::derive`): never a name, an email or a raw id, the same for a person in an organization for as long as the root lasts (a fresh store keeps it), different in another organization, and no one without the root can tell whose it is. No rotation yet.
- **Only with a person:** a call whose payer names one (a turn, a subagent, a compaction, a title, memory's tidy-up of their memory) carries it; a call for no one (the server's own work) carries none, and no organization's id stands in, since it would put every person of an organization under one name, the very thing this avoids.
- **Where the provider documents it, nowhere else:** OpenAI's `safety_identifier` (<https://developers.openai.com/api/docs/guides/safety-best-practices>); Anthropic's own API `metadata.user_id` ("Anthropic may use this id to help detect abuse", <https://platform.claude.com/docs/en/api/messages>). Other compatible servers, Bedrock and Vertex AI are sent nothing, as none documents a field and an unknown one may be refused.
- **OpenRouter gets none:** it documents `user` ("Per-end-user identifier for abuse isolation", <https://openrouter.ai/docs/api-reference/chat-completion>), but every request to it sends `provider.require_parameters: true` ("OpenRouter's preferences", above), and its docs don't say whether `user` counts as a parameter a provider must support; if it does, it could filter out providers that serve the model today. Until a real call shows it doesn't, OpenRouter is sent no id, and a person's misuse there still falls on the account.
- **Beside the prompt, never in it:** a request parameter, so a thread's prefix and its cache stay the same (`invariants.md`, 27).
- **Back to a person:** `glave people lookup <id>`, on the server's computer, reads the store and the root itself, makes the id of every person in every organization there, removed ones included, and prints the organization and the person that match. Only whoever holds the store and its root can, so it needs no role of its own.

## Metering

- Every call produces the content-free `model.responded` event, with usage, cost, the price list it was computed from, route and target, the target's service in a person's words, and the provider a router passed it on to (OpenRouter names it in each chunk). A turn's receipt says where it ran from these ("via OpenRouter (Anthropic)") and what it cost, from the service's own numbers where it reports them (OpenRouter's `usage.cost`). A model the server calls on its own computer (a local endpoint) is priced at nothing, so its calls report $0.00 as any other reports its cost, and no client guesses it. There is no separate spend database: cost reports are views over the log.
- Calls glave makes on its own (the judge, compaction summaries) are metered and attributed to the thread that caused them.
- Provider prompt caching is passed through and its savings recorded. A response cache is off by default.

## Media tools

Decided by the owner, 2026-11-12 (#1260), from an independent design that read every provider's capabilities first: the agent makes images, speech, sound, music and 3D models through tools of glave's own, the same on every deployment. A tool names what it does, never who does it, so the provider behind it can change without a thread or a model noticing. Threads keep calls by name and glave's own model is trained on them, so once a tool ships its name stays and its shape only grows: an argument added later is optional, and a result gains fields, never loses or renames one.

**Shared rules.**

- **A file argument** is a saved file the thread holds, `blob:<sha256>` (one it made, one the person added, one the gate kept), or a file on the thread's computer by its path, as `read` takes it; a Library asset, `asset:<id>`, later.
- **`quality`** is one enum on every tool that has it: `low` (seconds and cents, for trying ideas), `medium` (the default), `high` (slowest and dearest, for finals). The server's settings map each tier to a model and its settings; the interface never names a provider. An argument the tier's model can't honour moves the call to a model that can; when none can, the call is refused in one sentence.
- **A result is the files made**, each a saved file and its media type, as the model reads it: `{"files": [{"file": "blob:<sha256>", "media_type": "image/png"}]}`, each kept whole as the provider made it, sealed in the thread's blobs; audio entries add `duration_secs`. An image is also a `file` part after it, so a model that reads images sees what it made (the copy made fit to send, `session.md`, "Attachments") and a client draws it. Each entry also names `asset`, `asset:<id>`, the person's Library item that keeps it beyond the chat (`session.md`, "Library"), prefixed as `file` is so neither reads as a path once assets are file arguments; nothing else changes. A failure is an error result in a sentence the model can act on.
- **Long jobs, later.** Until `media_job` is built, a media call ends with its provider's answer or its timeout (5 minutes of silence), never a limit of glave's own, since the provider bills it either way; one that ends unanswered, or is stopped once sent, is settled at its hold, and the model is told it may still be made and billed and not to make it again unless the person asks. Then: every media call waits up to 4 minutes, then answers `{"job": <n>, "status": "running"}`, numbered per thread as commands in the background are. `media_job` (`job`, `wait_secs` default 240 and at most 600, `cancel`) waits again or cancels one, and with no `job` lists the thread's. Jobs outlive turns, at most 8 run at once in a thread, and none is retried, since each submission is billed; a job's hold lasts until it ends.

**Providers** are the server's choice, per tier, each reached through its own API, as no standard covers media: for images, OpenAI's and Google's own APIs where the server has an account at each, as Glave Cloud does ("Prices"), else OpenRouter's image API; for speech, ElevenLabs v4 Turbo, through OpenRouter or, on Glave Cloud, which has no OpenRouter, directly; ElevenLabs directly for sound effects and music, Tripo v3 directly for 3D. A tool is offered only where its service can be reached: on a laptop or a person's own server, through the person's own account there (their OpenRouter, a model account, `session.md`); on Glave Cloud, through the server's own. On a server that keeps credits it is offered only where one of its models is priced, since an unpriced one would refuse every call and stay in the thread's tools all the same. A thread's first call lists what is offered then; one offered later waits for a compaction or a new thread (`invariants.md`, 27).

**Paid as a model call is** ("Credits"): on a server that keeps credits, held before it is sent and charged after, to the thread's organization for the person whose work it is, each charge's kind `media`. The hold is the worst case of the model that serves it at its listed price: a tier's most output tokens (4,096 for `low`, 8,192 for `medium`, 65,536 for `high` by default) at its price for images out, its prompt, and 8,192 tokens for each image sent in, at its price for input; where its price is per image made, that price. The tiers' numbers come from the providers' own pages (2026-11-12): Nano Banana 2.1 makes a 1K image in 1,120 tokens and bills its thinking at a quarter of the image rate, so 4,096 leaves room for about 11,900 thinking tokens; GPT Image at quality `high` makes its largest standard size, 1536x1024, in 6,240 tokens; nothing is documented for `max`, and its largest image, 8,294,400 pixels, takes 32,906 tokens at `high`'s rate, so twice that; GPT Image reads every image in at high fidelity, 6,240 tokens for a 1536x1024 one beside its tiles' own. It settles at the cost the provider reports, else at that price, and a cost above the hold goes below nothing by that much, as a model call's does. A media call is billed whether or not its answer is read: one dropped once sent, ended with no answer that can be read, or answered saying nothing of what it used, settles at its hold; one its provider refused with an error, or that never reached it, at nothing, as no failed generation is billed and the next target is tried; an answer with no image, at the cost it reports. A tool whose model nothing prices (the server's settings, glave's price list or its catalog, "Prices") is refused before it is sent. Where no credits are kept, the person's own account pays, and nothing is held.

- **Filters and the floor hold** as for a model call ("A person's filters", "A server's floor"): a call through a router keeps to them, its providers read from the router's catalog; one that can't be kept to them is refused, never sent past them.

## Web search

Decided by the owner, 2026-11-14 (#1418): glave's own `web_search` (`session.md`, "Web search") goes through the gateway, which holds the search service's key and pays for each search as it pays for a model call.

- **One service, the server's:** Brave's Search API, its key from `GLAVE_SEARCH_KEY` alone, no setting naming it until a second service works; with no key the gateway serves no search and no thread is offered the tool. No port stands between them until a second service comes.
- **Priced whole:** each search costs the service's price for one, $0.005 at Brave's Search plan ($5 for 1,000, read 2026-11-14), written beside its adapter, since the service lists no price glave can read; it moves into glave's price list as a price per request ("Prices").
- **Held, then charged** ("Credits"): where the server keeps credits, a search that says whose work it is holds its price, then is charged at the cost the service reports, else its price, as `search`; refused before it is sent, with the sentence a model call gets, when the balance or the month's limit can't pay. Brave bills no search it refused (a rate limit's among them), so one refused is charged nothing; one sent and never answered, or dropped once sent, is charged its hold, as a media call's. Where no credits are kept, the key's own account pays, and nothing is held.
